使用自己的私人 Site URL；不要把它、帳號識別、紀錄 ID、照片 URL、備份或登入憑證貼進公開 Issue。只使用 [合成報告](../evidence/synthetic-blood-report.png)。不需要 Cloudflare 帳號、Wrangler remote、BYOC 或 AI API key。

已完成的桌面／Codex 實測不必重做：原生私人 Sites 部署、MCP 寫讀修正、PWA 顯示、合成照片人工確認後寫入，以及 6 筆紀錄／1 張原圖／7 筆稽核的清除還原。證據見 [2026-11-22 報告](../evidence/2026-11-22-final-acceptance-v2.json)。這些證據不代表下列手機及平台流程已通過。

- [ ] 手機 ChatGPT 與私人 Site 使用同一個擁有者帳號 A，並已連線該 Site 產生的個人 MCP；不要選到舊的 PetMCP 服務。
- [ ] 準備合成圖片及可用的第二真實帳號 B。B 由其本人登入，不交出密碼或 session。
- [ ] 選擇要測 teardown 的一次性測試 Site。現在保留使用的個人 Site 不在預設刪除範圍；需要另一個 Site 時也只能用原生 Sites 建立。

## B　手機 ChatGPT 的照片工具交接

1. [ ] 在手機 PWA 上傳合成報告，確認上傳成功並可查看原圖。
2. [ ] 回手機 ChatGPT，使用此 Site 的個人 MCP，輸入：「讀取我私人 PetMCP 最新的合成照片，列出寵物名稱、報告日期、原始數值、單位與不確定處。先給我核對，不要寫入。」
3. [ ] 確認出現真正的附件讀取工具結果，並核對草稿：LUNA (FICTIONAL)、2026-09-14，ALT 68 U/L、ALP 31 U/L、BUN 28 mg/dL、CREA 1.6 mg/dL、SDMA 13 µg/dL、PHOS 4.8 mg/dL、GLU 122 mg/dL、TP 7.1 g/dL。
4. [ ] 明確確認草稿後才保存到指定合成測試寵物，再要求 MCP 讀回；回 PWA 重新讀取並核對日期、8 筆原始值與照片連結。

**判定**：四步都取得實際結果才 pass。工具不可選、圖片無法傳回或只得到文字猜測時，保留非敏感錯誤與版本，記為 blocked／fail。不能用桌面 Codex 已通過代替；不將照片或醫療內容放入 ChatGPT 網址參數。

## C　ChatGPT 原生 Voice

- [ ] 從手機原生 ChatGPT 開啟 Voice，嘗試要求此個人 MCP 列出合成測試寵物；確認有工具呼叫及正確結果。
- [ ] 口述一筆明確標為合成測試的日常照護草稿，要求先讀回文字、日期及寵物供核對；在本人確認後才寫入。
- [ ] 結束 Voice，以 MCP 與 PWA 讀回同一筆紀錄，確認沒有誤寫、重複寫入或錯誤日期。
- [ ] 分別記錄「從 PWA 切換／開啟 ChatGPT」和「原生 Voice 使用 MCP」的結果。PWA 內沒有 ChatGPT Live iframe，也不承諾直接轉送麥克風。

若當下 Voice 不提供個人插件／工具，記 **blocked：平台能力不可用**，附 App 版本及介面證據。不能改接外部語音 API 或把一般語音轉文字當作 Voice＋MCP 通過。

## D　第二真實帳號隔離

**第一層：私人 Site 的受眾限制**

- [ ] A 保持登入，確認可讀自己的合成紀錄及照片。
- [ ] B 在獨立瀏覽器設定檔／裝置登入自己的帳號，開啟 A 的私人 Site、同一筆紀錄與照片入口，嘗試連線／呼叫 A 的個人 MCP。
- [ ] 確認 B 只能得到登入／無權限／找不到，不會收到 A 的紀錄、圖片、備份或稽核；記錄狀態碼／介面。不能用 A 的 cookie、token 或手動偽造身份 header 測 B。

**第二層：應用程式依 owner 隔離**

- [ ] 若私人受眾在入口就擋住 B，第一層可 pass，但不能因此宣稱資料列隔離已實測。
- [ ] 若需驗第二層，另用一次性原生 Sites 測試實例，經本人明確同意把 A、B 都列入該實例的受眾；不放寬正在使用的私人 Site。
- [ ] A、B 各自建立不同合成資料。B 用自己的身份要求讀取／修改／刪除 A 的已知紀錄與照片，必須遭拒；A 同樣不能存取 B 的資料。各自匯出只含自己的內容；拒絕後由資料擁有者讀回確認未變動。
- [ ] 若平台不支援此受眾／插件測試方式，第二層標 blocked，保留本機 owner 隔離測試作有限證據，不冒稱真實雙帳號通過。

只在私人紀錄保存兩帳號、Site 與資料 ID 的對照；公開證據僅留 A／B 標記、結果與遮罩截圖。

**必須先填：要刪除的測試 Site 名稱、原始 project_id、擁有者、刪除原因，以及本人明確同意。未完成前不執行刪除。**

1. [ ] 確認指定的是可丟棄測試實例，沒有其他人仍需使用；保存最新完整備份，驗證能還原並核對原圖。清除資料後若平台 Site 無法復原，備份可用於重新建立的原生 Site，但原 URL／project_id 不保證保留。
2. [ ] Agent 保存原生 Sites 可提供的部署前基線、刪除前 Site／受管資料庫／附件／個人插件清單；本人完成僅能在 UI 進行的確認。

4. [ ] Agent 從平台查回刪除結果、重新核對清單；本人確認舊 Site／插件不可用且其他 Site 正常。
5. [ ] 比對受管資源與部署前基線。若平台不提供 D1／R2 清除證明或完整清單，zero-diff 保持 **blocked**；網址失效、404 或只清空資料都不等於平台資源已歸零。
