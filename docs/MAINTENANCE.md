# 維護、備份、復原與移除

## 更新

先下載完整備份並確認包含紀錄、原圖 base64 與稽核。核對新公開 commit、CI 與差異，於隔離的 Sites 測試實例驗收後再原生部署到既有個人 project_id。已套用 migration 不修改；新增遷移須有備份與還原計畫。Sites 發布失敗也可能已套用 migration，先核對狀態，不盲目重送。

## 備份與還原

PWA「照片與備份」→「下載完整備份」。每張照片上限 5 MB；本版可還原備份最多 20 MB（照片原始總量 10 MB）、1000 紀錄／100 照片／5000 稽核。超限明確拒絕，不能說已完整備份。必要時逐張下載照片並找維護者規劃分批匯出；未完成可還原備份前勿刪除。

用空白的個人 Site／帳號，在同頁匯入 JSON。格式與關聯先驗證；有既有資料時拒絕覆蓋。還原期間停止其他分頁寫入。逐筆核對名字、日期、raw_value、unit、修正前後內容，下載照片比對位元組。備份不含原 owner ID；新 owner 由 Sites 登入身分決定。

## 刪除紀錄與全部資料

單筆刪除保留歷史稽核（含舊值），寵物有相關血檢／照護時會拒絕刪除。完全抹除時先匯出，再於 PWA「清除我的全部資料」輸入 `DELETE ALL PETMCP DATA`。這刪除目前使用者在本 Site 的紀錄、R2 物件與稽核，但不刪 Site。

## Teardown

1. 明確取得要移除的測試 Site 名稱、原始 project_id 與刪除同意；不得刪其他專案。
2. 先完成可還原備份，記錄部署前與現有 Sites 受管資源清單。
3. 原生 Sites 設定／管理功能停止發布並移除該 Site；撤銷對應個人 plugin。工具不可用時由擁有者在 ChatGPT UI 操作，不切到 Cloudflare。
4. 由 Sites 讀回專案移除結果，確認其受管 D1/R2 與 plugin 不再可用，與部署前清單作 zero-diff。
5. 不具備列出或驗證底層受管資源能力時，zero-diff 記為 blocked；不因網址無法開啟就推定所有資料已刪除。

## 額度與失敗

沒有排程背景任務。寫入／照片／備份失敗會即時在 UI 或 MCP 回報，不能把按下按鈕當成功。Sites 與 ChatGPT 的方案與限額不硬編免費數字；由帳號的官方方案／用量頁核對。CI 每次發布由 Agent 等待完成，維護者另開 GitHub Actions 失敗 email 通知。尚未提供 runtime 無人值守監控，不宣稱有。
